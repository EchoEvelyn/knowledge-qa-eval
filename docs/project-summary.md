# 企业内部知识库问答 Demo：项目梳理

## 项目是做什么的

搭建一个企业内部知识问答助手：员工用自然语言提问，系统从自己的知识库查找资料，再根据资料生成答案并标注来源；资料不足时，应明确说明无法回答。

目前使用虚构的 IT 服务台资料进行验证，不涉及真实企业数据。

## 整体流程

```text
准备企业资料 → 导入知识库 → 文档分段 → Embedding向量化
                                      ↓
用户提问 → 检索相关片段 → 大模型根据资料回答 → 输出答案和引用
                                      ↓
                         批量测试 → 评分 → 分析问题
```

Embedding用于把问题和文档转换成可比较的向量，帮助寻找语义相关的内容；大模型负责组织答案。Dify负责连接这些步骤，Python脚本负责批量测试、保存结果和计算指标。

## 项目推进过程

| 阶段 | 做了什么 | 当前状态 |
|---|---|---|
| 关键词检索 | 用结构化IT资料搭建检索接口 | 已完成基线测试 |
| 本地问答 | Python调用本地模型，根据检索资料回答 | 已完成20题测试与评分 |
| Dify工作流 | 将检索、模型生成和输出接成工作流，通过API评测 | 已跑通并归档 |
| 自有文档知识库 | 导入三份文档，使用Embedding进行向量检索 | 已完成新20题测试 |
| 指标评估 | 保存检索片段、答案、引用、评分及耗时，补充全库相关性审核 | 已生成报告和可复核标注 |

早期本地脚本和Dify的提示词、输出格式存在差异，后来进行了对齐。对齐测试说明，耗时差异不能全部归因于Dify本身。

## 当前知识库内容

三份测试材料分别覆盖：

- **账号与多因素认证**：密码重置、密码规则、账号锁定、认证手机更换、软件安装审批。
- **网络与VPN**：办公无线网络、访客网络、VPN接入条件、故障报障和访问权限。
- **共享文件与恢复**：文件夹权限、只读与读写、回收站、备份、历史版本和邮箱容量。

目前导出的知识库包含 **3份文档、77个片段**。

## 当前问答工作流

```text
用户输入
  → 知识库检索
  → 组装问题和参考片段
  → 大模型生成JSON答案
  → 解析JSON
  → 输出答案、资料不足标记等字段
```

- **检索模型**：bge-m3，用于Embedding。
- **生成模型**：本地Ollama运行的qwen3:4b。
- **检索数量**：每题返回前3个片段。
- **回答要求**：根据本次提供的资料回答，事实附引用，不凭常识补全未提供的信息。
- **JSON解析**：把模型输出整理为可供程序读取、展示和评分的字段。

## 已验证的结果

最新题集共 **20题：15道有答案题、5道资料不足题**。

| 指标 | 结果 | 说明 |
|---|---:|---|
| 请求成功 | 20/20 | 全部调用完成 |
| Hit@3 | 14/15 | 前3段至少找到一段有效证据 |
| Recall@3 | 86.67% | 对15题逐题计算后取平均，衡量相关片段找回程度 |
| Precision@3 | 40% | 返回片段中直接支持核心答案的比例 |
| 回答正确 | 13/15 | 按原用户评分统计 |
| 正确拒答 | 3/5 | 资料不足时明确说明且不编造 |
| 平均耗时 | 6.97秒 | 本轮20次完整请求的平均值 |
| P95耗时 | 10.33秒 | 描述本轮较慢请求的耗时水平 |

全量相关性标注覆盖 **15题×77段＝1155项**，由助手事后审核，保留正文、等级和理由，可进一步复核；不是独立人工盲评。Recall使用测试后导出的77段快照作为全集。

**Recall不等于答案是否足够完整。** 不同片段可能重复支持同一事实；即使没有找全全部相关片段，也可能已经具备正确回答所需的证据。

## 目前发现的问题

1. **检索遗漏**：D11没有找回报障所需的错误码、发生时间和客户端版本。
2. **生成理解错误**：D09已经检索到“仅允许受管电脑”，模型仍错误回答个人电脑可以接入。
3. **拒答不稳定**：部分资料不足题只重复问题，没有明确说明资料不足。
4. **分段较碎**：标题、日期等单独形成片段，可能占用检索位置。

这些问题说明：工作流跑通、检索命中、回答正确是三个不同层面的验收，不能只看调用成功。

## 下一步

- 调整分段方式，让标题与对应操作内容尽量保持完整。
- 优化资料不足时的回答，以及对“仅允许”“不保证”等限制条件的理解。
- 保留现有结果作为基线，每次只调整一类配置，再用同一题集比较。
- 增加口语化、跨片段和资料不足问题，检查效果能否推广到新问题。
- 后续接入有权使用的真实企业资料，补充文档更新、访问权限和来源追溯机制。

## 项目当前定位

这是一个已完成端到端运行和批量评测的知识库问答Demo，展示了从自有资料入库、语义检索、引用回答到评估分析的完整流程。它可以作为企业内部知识助手的验证原型，目前仍需提升检索与回答质量，尚未验证生产环境使用。
